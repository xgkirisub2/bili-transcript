# 成本分析：B 站视频解析工作流

测量时间：2026-10-21
环境：Windows 11 / Python 3.12.15 / RTX 4070 Ti 12GB / faster-whisper `large-v3-turbo`（CUDA float16）

> 测量基于重构前的脚本版；核心流程、默认参数和输出格式一致。数据目录现在默认在 `~/.bili-transcript/`。

## 1. 样本

| 视频 | 时长 | 解析路径 | 结果 |
| --- | --- | --- | --- |
| BV1wHnP6TEi4《艺 术 求 生》 | 19:42 | B 站 AI 字幕 | 630 段，覆盖 1174/1182 秒 |
| BV143nw6KExV《最后警告：人类历史上最大的泡沫，即将破裂》 | 21:35 | 无字幕 → 本地 ASR | 554 段，完整覆盖 |

## 2. 时间开销

### 2.1 有字幕：约 1.1 秒（进程级）

| 阶段 | 耗时 |
| --- | ---: |
| Python 启动 + import | ~0.50 s |
| 元数据 `get_info()` | 0.157 s |
| 字幕列表 + 字幕 JSON 下载 | 0.266 s |
| B 站官方 AI 总结接口 | 0.159 s |
| 写文件（txt/json/srt） | 0.013 s |
| **内部管线合计** | **0.596 s** |
| **进程总耗时（`time`）** | **~1.10 s** |

瓶颈：**进程启动**（约 45%）和**字幕 API 网络往返**（约 24%）。AI 总结接口占内部耗时约 27%，但它是可选的；如果只想要字幕，可以用 `--no-ai-summary` 或改成并发请求。

### 2.2 无字幕：约 37.5 秒（进程级，默认删除音频）

| 阶段 | 耗时 |
| --- | ---: |
| Python 启动 + import | ~0.55 s |
| 元数据 `get_info()` | 0.214 s |
| 字幕检查（无结果） | 0.144 s |
| B 站官方 AI 总结（无内容） | 0.155 s |
| 音频下载（30216 流，约 11 MB） | 1.111 s |
| **GPU 转写（large-v3-turbo）** | **35.321 s** |
| 写文件 | 0.013 s |
| **内部管线合计** | **36.959 s** |
| **进程总耗时（`time`）** | **~37.50 s** |

瓶颈：**GPU 转写占 95%**。音频下载已经不是瓶颈（1.1 秒）。ASR 吞吐约 **36.7 倍实时**（1295 秒音频 / 35.3 秒）。

### 2.3 首次运行的异常值：118.5 秒

同一视频第一次运行耗时 118.5 秒，其中 ASR 35.1 秒，音频下载约 82 秒。原因是当时选择的是 30232 音频流，该 CDN 流后来复测时直接读超时；切换到 30216 流后下载降到 1.1 秒。**这不是稳定态，当前默认配置已避开该问题。**

### 2.4 缓存命中：约 0.66 秒（进程级）

| 阶段 | 耗时 |
| --- | ---: |
| Python 启动 + import | ~0.42 s |
| 元数据 `get_info()` | 0.238 s |
| 读取缓存 | ~0.001 s |
| **进程总耗时** | **~0.66 s** |

缓存读取本身可以忽略；主要成本仍是进程启动和一次元数据请求。若做批量/常驻服务，这部分可以摊薄。

## 3. 存储开销

### 3.1 固定安装（一次性）

| 项目 | 大小 |
| --- | ---: |
| 项目 `.venv` | **2.3 GB** |
| — 其中 NVIDIA CUDA 库 | ~2.03 GB |
| — 其中 Python 包（含 bilibili-api、faster-whisper 等） | ~270 MB |
| faster-whisper 模型缓存 | **1.6 GB** |
| **固定合计** | **~3.9 GB** |

> 模型缓存在 `~/.cache/huggingface/hub/models--mobiuslabsgmbh--faster-whisper-large-v3-turbo`；仓库本身（不含 `.venv` 和用户数据）只有约 200 KB。

### 3.2 每条视频的增量（当前默认：ASR 后删除音频）

| 文件 | 有字幕视频（19:42） | 无字幕视频（21:35） |
| --- | ---: | ---: |
| transcript.txt | 20 KB | 22 KB |
| transcript.json | 84 KB | 88 KB |
| transcript.srt | 40 KB | 44 KB |
| summary.md（可选分析产物，不计入默认） | 8 KB | 12 KB |
| meta.json | 4 KB | 4 KB |
| ai_conclusion.json | 96 KB（有内容时） | 0（无内容时不保存） |
| audio.m4a | 无 | 0（默认已删除） |
| **合计** | **~252 KB** | **~172 KB** |

按视频时长折算：

| 场景 | 每小时存储 |
| --- | ---: |
| 有字幕（含 AI 总结） | ~0.77 MB/小时 |
| 有字幕（不含 AI 总结） | ~0.47 MB/小时 |
| 无字幕，音频删除 | ~0.48 MB/小时 |
| 无字幕，保留音频（`--keep-audio`，约 66 kbps） | ~31 MB/小时 |

本次实验的两个视频合计输出目录只有 **432 KB**（现在默认位于 `~/.bili-transcript/data/`）。音频保留时，仅一条 21:35 的视频就会占约 11 MB，是其他所有文件总和的 60 倍以上。

### 3.3 结论

- **固定成本是主要开销**：CUDA 库 2.0 GB + 模型 1.6 GB ≈ 3.6 GB；如果只用 CPU 或换小模型，可以显著降低。
- **单条视频的增量成本很低**：默认删除音频后，20 分钟视频约 0.2 MB；即使一年处理 1000 条 20 分钟视频，也只有约 200 MB。
- **保留音频是存储放大器**：会从 ~0.2 MB/条变成 ~11 MB/条，约 55 倍。默认删除是对的。

## 4. 费用与资源

- **API 费用：0**。只使用 B 站公开接口和登录态，不调用付费 AI API。
- **转写费用：0**。本地 GPU 推理。
- **电费**：以 4070 Ti 约 200–250 W、转写 35 秒估算，约 0.002–0.0026 kWh；按 ¥0.6/kWh 计算，约 **¥0.001–0.0016 / 21 分钟视频**，可忽略。
- **网络流量**：无字幕视频需下载约 11 MB 音频；有字幕视频只下载几十 KB 字幕 JSON。
- **固定磁盘**：约 3.9 GB（`.venv` 2.3 GB + 模型 1.6 GB）。

## 5. 已做的优化

1. **音频流选择**：优先 30216（约 66 kbps），避开慢速/超时的 30232 流；21 分钟视频下载从约 82 秒降到 1.1 秒。
2. **ASR 后默认删除音频**：单条视频存储从约 11 MB 降到约 0.17 MB；需要保留时用 `--keep-audio`。
3. **空 AI 总结不落盘**：接口返回 `code=-1` 或无内容时不写 `ai_conclusion.json`。
4. **分阶段计时**：`--json` 新增 `timings` 字段，便于后续定位瓶颈。
5. **缓存**：按 BV/分P 复用文字稿，缓存命中约 0.66 秒。

## 6. 还可以怎么优化

| 目标 | 做法 | 预期收益 | 代价 |
| --- | --- | --- | --- |
| 有字幕视频更快 | 有字幕时跳过 AI 总结，或与字幕并发 | 省 ~0.15 s/条 | 少一份官方摘要辅助 |
| 缓存命中更快 | 命中缓存时先读 `meta.json`，跳过 `get_info()` | 0.66 s → ~0.42 s | 少量代码改动 |
| 批量处理更快 | 常驻进程/批处理，复用模型和 Python 进程 | 每条省 ~0.5 s 启动 + 1–2 s 模型加载 | 需要新增 batch 入口 |
| ASR 更快 | 换 `distil-large-v3` / `small` / `medium` | 2–5 倍 | 中文准确率下降 |
| 存储更小 | CPU int8 + 小模型 | 省 ~2 GB CUDA 库和 ~1 GB 模型 | 转写明显变慢 |
| 网络更省 | 只处理有字幕视频；无字幕时先确认是否真的需要全文 | 省 11 MB/条 | 依赖视频是否有字幕 |

## 7. 测量口径与注意事项

- 时间是单次测量的结果，受 B 站 CDN、网络波动、GPU 温度和视频内容影响；ASR 耗时与音频时长近似线性。
- 第一次安装还包括下载 1.6 GB 模型和约 2.3 GB 依赖，这部分属于一次性成本，未计入上面的稳态时间。
- 存储大小按 Windows NTFS 簇大小统计，小文件会按 4 KB 对齐，实际字节数可能略小。
- 音频码率和视频内容会影响音频大小；本样本的 30216 流约 66 kbps。
- 文字稿可直接交给调用方分析；本工具不默认生成 summary，也不产生额外 API 费用。
